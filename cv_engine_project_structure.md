# CV Engine — структура проекта для прототипа системы мониторинга усталости

## Описание

Этот документ описывает **изолированную часть проекта**, за которую отвечает разработчик CV-модуля:  
модуль компьютерного зрения для оценки **усталости** и **отвлечённости** пользователя по видеопотоку с камеры.

Документ специально написан так, чтобы по нему можно было **сразу начать разработку**, не дожидаясь фронтенда, UI и общей интеграции.

---

## 1. Цель твоей части проекта

Ты разрабатываешь отдельный модуль/сервис, который:

- получает кадры с камеры или из видеофайла,
- находит лицо и ключевые точки,
- вычисляет метрики по глазам и положению головы,
- отслеживает их во времени,
- формирует промежуточные CV-состояния,
- отдаёт наружу результат в структурированном виде.

### Важно
Ты **не занимаешься**:
- уведомлениями,
- UI,
- текстами подсказок,
- экраном статистики,
- общей бизнес-логикой приложения.

Ты делаешь именно **CV-движок**.

---

## 2. Что должно получиться в конце

На выходе должен быть отдельный сервис или модуль, который для каждого кадра/окна времени возвращает данные примерно такого вида:

```json
{
  "timestamp": 1710000000.123,
  "face_detected": true,
  "face_confidence": 0.91,
  "quality": {
    "low_light": false,
    "bad_pose": false,
    "occluded": false
  },
  "eye": {
    "ear_left": 0.24,
    "ear_right": 0.23,
    "ear_avg": 0.235,
    "blink_detected": false,
    "blink_duration_ms": 0,
    "perclos_30s": 0.18
  },
  "attention": {
    "face_present": true,
    "head_deviation_score": 0.12
  },
  "cv_state": {
    "eye_state": "open",
    "fatigue_score": 0.41,
    "attention_score": 0.83
  }
}
```

## 3. Рекомендуемый стек

Для MVP лучше использовать простой и надёжный стек:

- **Python**
- **OpenCV** — работа с кадрами, видео, визуализация, отладка
- **MediaPipe** — face landmarks / landmarks глаз и лица
- **NumPy** — вычисления
- **FastAPI** или **WebSocket** — для локального API/стрима результатов
- **Pydantic / dataclasses** — строгие структуры данных
- **Matplotlib / CSV / JSON logs** — отладка и анализ метрик

## 5. Назначение папок и модулей

## `app/camera`
Отвечает за получение видеопотока.

### Что должно быть внутри
- чтение с веб-камеры
- чтение из видеофайла
- контроль FPS
- ресайз / downscale
- базовая нормализация кадра

### Задача
Сделать единый интерфейс, чтобы источник видео можно было менять без переписывания логики.

---

## `app/landmarks`
Отвечает за обнаружение лица и извлечение ключевых точек.

### Что должно быть внутри
- детектор лица
- landmarks лица
- landmarks глаз
- точки для head pose
- confidence детекции

### На выходе
Структура вида:
- лицо найдено / нет
- набор точек
- confidence
- вспомогательные признаки качества

---

## `app/metrics`
Содержит основные вычисляемые признаки.

### Основные модули

#### `ear.py`
Расчёт Eye Aspect Ratio:
- для левого глаза
- для правого глаза
- среднее значение

#### `blinks.py`
Логика морганий:
- начало моргания
- конец моргания
- длительность
- количество за окно времени

#### `perclos.py`
Расчёт PERCLOS:
- процент времени, когда глаза закрыты
- окно 30–60 секунд

#### `head_pose.py`
Оценка положения головы:
- отклонение влево/вправо
- наклон
- поворот
- расстояние от baseline

#### `fatigue_score.py`
Сбор rule-based fatigue score из нескольких признаков:
- PERCLOS
- длительность морганий
- длинные закрытия глаз

#### `attention_score.py`
Признаки отвлечённости:
- лицо пропало
- лицо нестабильно
- сильное отклонение головы

---

## `app/temporal`
Отвечает за временную обработку данных.

### Что должно быть внутри
- rolling window
- сглаживание шумных сигналов
- дебаунс событий
- накопление статистики по времени

### Зачем это нужно
Без temporal-логики CV будет дёргаться и давать много ложных срабатываний.

---

## `app/calibration`
Отвечает за персональную настройку пользователя.

### Что должно быть внутри
- профиль пользователя
- сбор baseline в спокойном состоянии
- сохранение baseline-значений
- применение baseline в реальном времени

### Что калибровать
- baseline EAR
- baseline head pose
- baseline blink duration

---

## `app/quality`
Проверка качества сигнала.

### Что отслеживать
- плохое освещение
- лицо не найдено
- лицо слишком маленькое
- частичное перекрытие
- плохой угол головы
- низкая уверенность модели

### Зачем
Лучше вернуть `low_confidence`, чем выдать ложное состояние усталости или отвлечённости.

---

## `app/state`
Преобразует числовые метрики в промежуточные CV-состояния.

### Примеры состояний

#### Eye state
- `open`
- `partially_closed`
- `closed`
- `blink`
- `unknown`

#### Fatigue state
- `normal`
- `warning`
- `high`

#### Attention state
- `attentive`
- `possibly_distracted`
- `absent`
- `low_confidence`

---

## `app/api`
Способ общения с внешним приложением.

### Для MVP достаточно
- локального HTTP API
- или WebSocket-потока JSON-сообщений

### Задача
Сделать так, чтобы твой движок можно было подключить снаружи без прямой зависимости от внутреннего кода.

---

## `app/debug`
Инструменты для собственной отладки.

### Что полезно сделать
- рисование landmarks поверх кадра
- отрисовка текущих метрик
- логирование в JSON / CSV
- сохранение графиков по времени

## 6. Этапы разработки

## Этап 0. Подготовка каркаса

### Цель
Поднять проект, который можно запускать локально.

### Что сделать
- создать проект `cv-engine`
- подключить зависимости
- реализовать запуск с камеры
- реализовать запуск с видеофайла
- показать кадр на экране
- сделать базовую структуру папок

### Результат этапа
Рабочий каркас проекта с видеовходом.

---

## Этап 1. Детекция лица и landmarks

### Цель
Научиться стабильно получать лицо и точки глаз/лица.

### Что сделать
- подключить landmark detector
- детектировать лицо
- извлекать landmarks
- выделить точки глаз
- выделить точки для head pose
- добавить confidence

### Результат этапа
На каждом кадре доступны:
- `face_detected`
- `confidence`
- coordinates landmarks

---

## Этап 2. Базовые метрики глаз

### Цель
Получить первые реальные признаки усталости.

### Что сделать
- реализовать EAR
- вычислять EAR для обоих глаз
- сделать классификацию:
  - глаз открыт
  - глаз частично закрыт
  - глаз закрыт
- реализовать blink detection
- фиксировать длительность морганий

### Результат этапа
Появляются:
- `ear_left`
- `ear_right`
- `ear_avg`
- `blink_detected`
- `blink_duration_ms`

---

## Этап 3. Temporal smoothing

### Цель
Стабилизировать измерения.

### Что сделать
- rolling window
- сглаживание EAR
- фильтрация шумных кадров
- debounce морганий
- буфер последних N секунд

### Результат этапа
Появляются устойчивые сигналы, пригодные для принятия решений.

---

## Этап 4. Метрики усталости

### Цель
Собрать fatigue-related признаки.

### Что сделать
- реализовать PERCLOS
- считать blink rate за окно времени
- считать среднюю длительность морганий
- считать длинные закрытия глаз
- собрать fatigue score v1

### Результат этапа
Появляются:
- `perclos_30s`
- `blink_rate_60s`
- `avg_blink_duration_60s`
- `long_blinks_60s`
- `fatigue_score`

---

## Этап 5. Метрики отвлечённости

### Цель
Собрать признаки потери внимания.

### Что сделать
- отслеживать исчезновение лица из кадра
- считать длительность отсутствия лица
- оценивать сильное отклонение головы
- собирать attention score

### Результат этапа
Появляются:
- `face_present`
- `face_missing_duration_ms`
- `head_deviation_score`
- `attention_score`

---

## Этап 6. Калибровка пользователя

### Цель
Уйти от жёстких общих порогов.

### Что сделать
- режим baseline-сессии 30–60 секунд
- сбор нормальных значений EAR
- сбор нормального положения головы
- сбор средней длительности моргания
- сохранение calibration profile

### Результат этапа
Появляются персональные пороги, а не общие оценки “для всех”.

---

## Этап 7. CV state layer

### Цель
Собирать понятные CV-состояния из чисел.

### Что сделать
- реализовать `eye_state`
- реализовать `fatigue_state`
- реализовать `attention_state`
- собрать единый `cv_state_builder`

### Результат этапа
Наружу можно отдавать не только метрики, но и промежуточные состояния.

---

## Этап 8. API и интеграция

### Цель
Сделать модуль независимым от UI.

### Что сделать
- оформить JSON-схемы ответа
- поднять WebSocket или HTTP API
- сделать endpoint/стрим текущих результатов
- реализовать start/stop session
- реализовать debug mode

### Результат этапа
Движок можно запускать отдельно и подключать к нему внешнее приложение.

---

## Этап 9. Тестирование и валидация

### Цель
Понять, насколько метрики адекватны в реальных сценариях.

### Что сделать
Подготовить тестовые кейсы:
- нормальная работа
- частые моргания
- длинные закрытия глаз
- взгляд в сторону
- уход из кадра
- плохой свет
- очки
- закрытие лица рукой

### Что логировать
- timestamp
- EAR
- PERCLOS
- blink events
- fatigue score
- attention score
- quality flags

### Результат этапа
Можно тюнить thresholds и фиксить слабые места не вслепую.

## 8. Что можно не делать сразу

Чтобы не утонуть на старте, **не делай в первой версии**:

- полноценный gaze tracking
- ML-классификатор усталости
- сложную нейросетевую fusion-модель
- поддержку всех сложных кейсов сразу
- продакшн-инфраструктуру
- базу данных
- облачный backend

### MVP для твоей части должен быть таким
- landmarks
- EAR
- blink detection
- PERCLOS
- face present/absent
- head deviation
- fatigue score v1
- attention score v1
- JSON output

## 12. Итог

Твоя часть проекта — это **изолированный CV engine**, который:
- работает сам по себе,
- не зависит от UI,
- получает видео,
- считает метрики,
- формирует состояния,
- отдаёт наружу результаты в понятном формате.

Самый правильный путь:
1. сначала landmarks,  
2. потом метрики глаз,  
3. потом temporal-логика,  
4. потом fatigue/attention scores,  
5. потом calibration и API.

Так ты быстрее получишь **рабочий baseline**, который потом можно улучшать и интегрировать в полноценное приложение.
